# Лабораторна робота № 4. Алгоритми над списками

Котяш Тарас, КН-3/1. Основи програмування та алгоритмічні мови, І семестр 2026/2027.

Запуск із папки проєкту з установленим .NET 9 SDK:

```powershell
dotnet run -c Release
```

## Результати для варіанта 14

Основний список із генератором `new Random(14)`:

```text
[-9, 8, 1, 1, 1, 6, -6, -1, 4, -1, 2, -2, -5, 5, 5, 5, 5, 3, -8, 4]
```

1. **Побудова.** Додатні непарні числа в початковому порядку — `[1, 1, 1, 5, 5, 5, 5, 3]`. Кількість — 8.
2. **Вилучення.** Сума чисел дорівнює 18, початкове середнє — 18 / 20 = 0,9. Хибний цикл пропустив **−1 і −5** (початкові індекси 7 і 12). Після вилучення −6 число −1 зсунулося на його місце, а цикл уже перейшов до наступного індексу. Те саме сталося з −5 після вилучення −2. Обхід з кінця й побудова нового списку дали `[8, 1, 1, 1, 6, 4, 2, 5, 5, 5, 5, 3, 4]`. Поелементна перевірка повернула `true`.
3. **Злиття.** Два індекси проходять списки довжиною 13 і 9. На кожному кроці додаємо менше з двох поточних чисел, потім дописуємо хвіст. Обидва входження 20 збережено. Результат містить 22 числа, перевірка порядку — `true`. Часова складність — O(n + m).
4. **Розділення.** Поріг дорівнює 23 % 7 = 2. До першого списку потрапило 10 чисел, до другого — теж 10. Саме число 2 належить другому списку. Перевірка кількості повернула `true`.

## Замір часу

Один запуск на Linux x64, .NET 9, Release. Перед заміром кожна операція пройшла прогрів на 1 000 елементів. Час підготовки списку для пошуку виключено із заміру.

| Операція | Час, мс |
|---|---:|
| 100 000 × Add без заданої місткості | 1,1662 |
| 100 000 × Add з місткістю 100 000 | 0,1980 |
| 100 000 × Insert(0, x) | 278,2929 |
| 1 000 × Contains(-1) серед чисел від 0 до 99 999 | 15,4627 |

1. Вставка на початок тривала **у 238,6 раза довше** за Add без заданої місткості. List використовує масив. Для вставки на початок він зсуває всі наявні елементи на одну позицію. За весь цикл це 0 + 1 + … + 99 999 = 4 999 950 000 зсувів. Серія таких вставок має складність O(n²), а серія додавань у кінець — амортизовано O(n).
2. Коли внутрішній масив заповнюється, List виділяє більший масив і копіює елементи. Резервування 100 000 місць усуває проміжні виділення пам’яті й копіювання.
3. Відсутність −1 можна встановити тільки після перегляду всього списку. Тисяча пошуків охоплює 100 мільйонів елементів. Для порівняння, цикл Add записує в кінець лише 100 тисяч елементів із періодичним розширенням масиву.

## Крайові випадки

| Вхід | Завдання | Очікувано | Отримано |
|---|---|---|---|
| Порожні списки | 1–4 | Порожні результати, дві порожні групи | 1, 2, 3 → `[]`; 4 → `[]` та `[]` |
| Один елемент `[3]` | 1, 2, 4 | Побудова і вилучення повертають 3; число йде до другої групи | 1 → `[3]`; 2 → `[3]`; 4 → `[]` та `[3]` |
| Жоден не підходить | 1, 2 | Для `[-2,0,4]` немає додатних непарних; у `[2,2]` нічого вилучати | 1 → `[]`; 2 → `[2,2]` |
| Усі підходять | 1, 2 | Для `[1,3,5]` зберегти всі; для № 2 такий непорожній вхід неможливий | 1 → `[1,3,5]`; 2 → немає такого входу¹ |
| Один список для злиття порожній | 3 | В обох порядках отримати другий, непорожній список | `[]` і `[2,4]` → `[2,4]`; у зворотному порядку → `[2,4]` |

¹ Якби всі числа були строго менші за середнє, їхня сума була б меншою за середнє, помножене на кількість елементів. За означенням середнього ці величини рівні.
