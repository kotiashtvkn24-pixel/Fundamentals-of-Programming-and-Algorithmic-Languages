# Лабораторна робота №9
Котяш Тарас, КН-3/1. Реалізація та порівняння алгоритмів сортування.

## Запуск
`dotnet run -c Release`

## 1. Бульбашка з прапорцем
Порівнюються сусіди; якщо обмінів немає, алгоритм завершується. Кожен обмін — два записи. Програма друкує трасування перших 9 чисел після кожного проходу.

## 2. QuickSort
Опорний елемент — середній. Два індекси рухаються назустріч, навіть якщо ключі рівні. Тому однакові елементи не спричиняють квадратичної поведінки в цій реалізації. Рекурсія для меншої ділянки обмежує глибину стека.

## 3. Два ключі
Складене порівняння спочатку порівнює групи, а при рівності — бали. Альтернатива: стабільна бульбашка спочатку за балом, потім за групою. Другий прохід зберігає порядок балів усередині груп. Обидва результати перевіряються. За однакових обох ключів порядок записів може відрізнятися через нестабільність QuickSort.

## 4. Порівняння
Таблиці фактичних лічильників друкуються програмою. На відсортованому масиві бульбашка виконує n−1 порівнянь і нуль записів. На зворотному вході кількість обмінів велика; повтори зменшують її. QuickSort із середнім опорним не має квадратичної поведінки на звичайному відсортованому вході.

## 5. Час та стабільність
Release, Stopwatch, прогрів, мінімум трьох вимірювань. Копіювання і перевірки поза вимірюваним інтервалом. Для c=4 додатковий експеримент стосується студентів, тому час двох ключів вимірюється окремо, а не на числових масивах.

Очікування до запуску: Bubble та OrderBy стабільні; QuickSort та Array.Sort не гарантують стабільності. У ЛР6 усі бали різні, тому додатково перевіряється копія з округленими до десятків балами. OrderBy використовується лише як еталон стабільності, не у власних алгоритмах.

## 6. Висновки
1. Виміряне відношення порівнянь на випадковому вході n = 10 000: 315,31, що менше за лекційне 376. Воно може відрізнятися від 376 через повтори, ранню зупинку бульбашки та особливості розділення QuickSort.
2. Array.Sort застосовує інтроспективне сортування, зокрема вставки для малих ділянок і перехід до пірамідального сортування за надмірної глибини. Власний алгоритм також витрачає час на лічильники.
3. Для 100000 записів із ключем 0–300 обираю стабільне сортування підрахунком: O(n+301), додатковий буфер зберігає порядок однакових ключів при розміщенні елементів.
