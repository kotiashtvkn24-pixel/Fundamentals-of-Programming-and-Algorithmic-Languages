# Лабораторна робота 8. Алгоритми пошуку та їх порівняння
Котяш Тарас, КН-3/1. C# / .NET 8.

## Запуск
`dotnet run -c Release`

## 1. Лінійний пошук
Відсутній бал 101 потребує перевірки всіх елементів, тому цей запит найдорожчий.

## 2. Бінарний пошук і поломки
1. `lo < hi` пропускає останнього кандидата: на масиві [73] пошук 73 повертає -1.
2. `lo = mid` може залишити межі незмінними; для відсутнього 101 цикл обмежено 100 порівняннями.
3. `(lo + hi) / 2` може переповнити int, коли сума індексів перевищить 2147483647. Це можливо від 1073741825 елементів; на 100000 не проявляється. Програма окремо демонструє арифметичну модель.
4. Без сортування напрямок відкидання половини не обґрунтований. Фактично пропущено 84 зі 100 запитів (1554 порівняння).

## 3. Межі
LowerBound — перший бал >= 73, UpperBound — перший бал > 73. Різниця індексів дорівнює кількості входжень. Кількість порівнянь логарифмічна незалежно від кількості повторів, бо кожен крок зменшує інтервал приблизно вдвічі. Кратність 7 не є монотонною умовою, тому пошук межі не гарантує правильної відповіді.

## 4. Інтерполяційний крок
Перша позиція обчислюється пропорційно балу; далі виконується звичайний бінарний пошук. На рівномірно розподілених ключах це може зменшити кількість порівнянь. Нерівномірний розподіл погіршує прогноз, але наступний бінарний пошук зберігає коректність.

## 5. Вимірювання
100 запитів на кожному розмірі. Час: Release, прогрів, Stopwatch, мінімум із трьох запусків; сортування включено в час, копіювання — ні. Для часу використано невідсортований масив і однакові запити. Через малий діапазон балів лінійний пошук часто знаходить збіг набагато раніше, ніж n/2.

## 6. Висновок
1. У виміряному діапазоні до 100 запитів сортування не окупилося, зокрема й поблизу теоретичних 34. Точне значення точки окупності не встановлено. Повтори балів, вартість сортування, доступ до пам'яті та виклики делегатів впливають на результат. Якщо виграшу немає до 100, точку не встановлено в перевіреному діапазоні.
2. Бінарний пошук дозволяє знайти перший бал не менший за 73 та кількість записів у діапазоні 73–83. Звичайні HashSet/Dictionary без додаткового індексу не підтримують такі запити за порядком ключів напряму.
3. Для потоку зі змінами та запитами на рівність доцільний Dictionary з кількістю записів за балом; для рідкісних запитів можна використати перебір. Повторне сортування після кожної зміни має зайві витрати.
